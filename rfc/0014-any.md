# RFC 0014: `opaque` — Explicit Erasure with Checked Recovery

- **Status:** Draft
- **Date:** 2026-08-23
- **Revised:** 2026-09 — the builtin-surface amendment: the erasure box is
  the **primitive `opaque`** (declared `builtin primitive`, never a
  class), its `new` and `downcast` are BOTH member statics on the
  primitive, and the name is ambient — no `use` gates it (RFC 0028
  revised). The free `downcast<T>(o)` fn is removed; the old `Opaque`
  spelling is gone at every layer. Rust-side internals keep their names
  (`TY_OPAQUE`, `CellData::OpaqueBox`, `Value::Opaque`, `RutOpaque`).
- **Revised:** 2026-09-20 — repr notes added (§"Repr notes"): the two
  box tiers fixed in place by the native-fastpath audit — rut-minted
  `opaque(v)` boxes carry the value INLINE in the cell
  (`CellData::OpaqueBox { val: Slot }`, no Rust allocation), host
  payload boxes (`OpaqueBox<T>`) draw their block from an arena-owned
  bounded pool. Surface unchanged.
- **Revised:** 2026-09 — the opaque-is law (the opaque-is batch): `is`
  no longer sees through the box. `o is T` / `o is I` answer by the
  box — false for every payload type, concrete AND trait — and
  `o is opaque` (alias spellings included) stays `true`; recovery is
  `downcast<T>` only. Runtime-only change (artifact VERSION 10 → 11):
  the `IsType`/`IsTrait` op bodies answer by the cell's own type;
  `TidOf` — downcast's match test — keeps the payload read as the ONE
  legitimate see-through. The concrete-`is X` case is left to the
  runtime compare, not typeck-folded, so the primitive and its alias
  spellings cannot diverge.

  RFC 0025 (host fns & declaration files)

## Summary

`opaque` is the **erasure-box engine primitive**: a concrete type whose
values box any value — **forgetting the static type and keeping the
runtime type for downcast only** (`is` names the box, never the
payload) — the controlled replacement for `any`, built on
reification (RFC 0015). Erasure is a *method call you write*; the static
type system never loosens, and rut keeps **no cast syntax at all**
(`as` is reserved and always errors, RFC 0002 §4).

- `builtin primitive opaque` — declared in `core`'s declaration file
  (RFC 0025, revised — the engine's own contract) with both members as
  **statics on the primitive**:

  ```rut
  builtin primitive opaque {
      fn new<T>(v: T) -> Self;
      fn downcast<T>(o: Self) -> (T, bool);
  }
  ```

  A surface statement over the boot table, never a class (builtin-
  surface: like `str`/`bytes`, the Rust-side representation is
  unchanged) — backed by the same `RutOpaque` cell kind the VM
  already uses for host opaques (RFC 0016 §5). Construction **is**
  erasure — `opaque.new(v)`, the primitive's member static:
  **`opaque.new(v) -> opaque`** — every value can become `opaque`, and since
  every non-primitive is already a shared cell (RFC 0016 §1), the box
  **stores the handle: zero-copy, identity-preserving** — mutations
  through the original name are visible through the box. `opaque.new(x) ==
  opaque.new(x)` is `false` (two boxes, RFC 0012 §8) — box once, compare
  boxes.
- `opaque.downcast<T>(o) -> (T, bool)` — checked recovery, the second
  member static. `T` must be
  **concrete** — a trait-typed type argument (any `I`) is a compile
  error (RFC 0012 §3); trait-typed
  values have no recovery path by design. `.1` is `false` on mismatch
  and `.0` is then `T`'s zero value — never a trap. (The free
  `downcast<T>(o)` fn is REMOVED — the spelling diagnoses from the
  removal table with `opaque.downcast<T>(o)` as the fix, RFC 0028 v1.1.)
- **Host payload boxes** (RFC 0023/0026): the embedder can news the box
  itself — `OpaqueBox::alloc(vm, any_rust_value)` — behind the same
  `opaque` surface. The payload is Rust, so rut sees only the box:
  `o is opaque` is `true`, `o is T` misses for every rut `T`, and
  `opaque.downcast<T>` fails (`.1 == false`) for every `T` (the box's runtime type is a
  reserved host sentinel no table index can equal — the miss is checked,
  never a trap). The host borrows the payload back typed
  (`with`/`with_mut`, call-scoped, borrow-guarded per RFC 0023 §2); the
  payload's Rust `Drop` runs when the box's rc hits 0 (RFC 0016 §3).
- `o is X` **names the box, never the payload** (revised 2026-09 — the
  opaque-is law; this bullet's earlier "see through the box" reading is
  retired): concrete `T` and trait `I` BOTH miss — the box answers by
  its own type (`TY_OPAQUE`, whose vtable has no impl rows), so `o is
  T` is `false` for every payload type, `o is I` probes nothing, and
  the one check that names what it is — `o is opaque`, or the same
  type under an RFC 0043 alias spelling — is `true`. The boxed value
  is recoverable only through `opaque.downcast<T>(o) -> ?T`, whose
  match test (`TidOf`) keeps reading the payload — the ONE legitimate
  see-through (RFC 0012 §3, RFC 0015 §6). `x is opaque` (on a non-box
  receiver) is the ordinary concrete test for the box type itself.
- **That is the whole API** — apart from the three layout accessors of
  RFC 0015 §3 (`type_id()`, `size()`, `as_bytes() -> bytes`): no
  methods, no fields, no `f""` formatting. An
  `opaque` box can't do anything until it is recovered — which is exactly how
  it differs from gradual typing.
- Crossing isolates: allowed iff the boxed value's type is crossable
  (RFC 0021 §3), checked at runtime via the type descriptor.
- Also the host-FFI escape hatch for host data with no static shape
  (RFC 0023).

`opaque` is a **concrete primitive, not a lattice node**: it composes in
every type position trivially (`Vec<opaque>`,
`[opaque]`, fields, returns) because it is just a type — there
is no widening to it (the trait tier is `exact concrete > I`,
RFC 0031 §4). A
`Slice<T>`-typed value is **not boxable** (`opaque.new(..)` rejects slices — as it
rejects any trait-typed value — while fixed `[T]` boxes fine:
it is concrete, and its TypeId covers `T` and `N`). Slices are never
boxed, period.

## IR contract (why `opaque` does not break optimization)

1. **Boxes are never re-sealed.** The `opaque.new(v)` cell is written once
   at construction; store-style writers swap whole cells, never retype
   one.
2. **`downcast` is therefore pure** in `(cell, T)`: the compiler may CSE
   repeated downcasts of the same cell, hoist invariant checks out of
   loops, and cache results — validity is permanent.
3. **`downcast` is a refinement point**: within the `.1 == true` branch the
   value's lattice position is *exact concrete type* — everything
   downstream optimizes as if the value had never been erased.
4. **Downcast chains over one cell fold to a `TypeId` switch** (jump
   table), the erasure analogue of exhaustive `when`.
5. **`opaque` is a storage type, not a flow type**: lints flag
   downcasts inside loop bodies and `opaque` parameters/returns on
   non-storage functions. The hot path keeps concrete types.

Mechanically none of this is op magic (RFC 0032 §1.1): `opaque.downcast<T>` is
a generic **prelude function** over the type machine's two primitives —
`tidof` (read the cell's runtime `TypeId`), `icmp`, `br`, a guarded
`unbox`, `optsome`/`optnone` on the arms; `opaque.new(v)` is its mirror, an
internal-native call (RFC 0022 §2). Both names are ambient core
builtins (RFC 0028 revised — no `use`). The check being visible dataflow is
what makes 2 and 4 ordinary optimizations over a pure load — an opaque
`downc` op would block both.

The lattice machinery itself is RFC 0031 §4. See
**`demo/src/examples/opaque.rut`**. The motivating user-land pattern — a
tur-style reactive store, reactivity as a **library** over `opaque`
(`state` / `source` / `derive` / `mutation` / `watch` / `Store`, with an
`Atom` trait unifying the three atom kinds for `watch`) — has this
shape:

```rut
trait Atom { fn atom_id(self) -> u32; }

pub class State<T> {
    id: u32;
    seed: opaque;                 // first read materializes it

    fn new(ids: Ids, v: T) -> Self {
        return Self { id: fresh(ids), seed: opaque.new(v) };
    }
}

impl Atom for State<T> {
    fn atom_id(self) -> u32 { return self.id; }
}
```

Every value lives in the store as an `opaque` cell keyed by atom id —
`opaque.new(v)` in, `opaque.downcast<T>` out, `is` for the checks — so a
heterogeneous store is one table and no language magic: the atoms are
`State<T>` / `Source<T>` / `Derived<T>`, `watch(a, cb)` is a
change-only callback on any `Atom`, and `mutation` handlers are
dispatched against the store rather than called as setters.

## Repr notes — the two box tiers (2026-09, native-fastpath audit)

The batch that moved the host map crossings off `opaque` mints audited
what a box costs to make and to die, and fixed the two tiers in place.
The surface is UNTOUCHED: `opaque(v)` / `opaque.new(v)`,
`opaque.downcast<T>(o)`, `o is T`, and the layout accessors behave
exactly as specified above — no version bump, no new op, no repr the
program can observe.

1. **Rut-minted boxes — the payload is INLINE, not a Rust box.**
   `opaque(v)` lowers to `Op::Box` and executes as
   `Heap::alloc_opaque`: one cell of kind
   `CellData::OpaqueBox { val: Slot, val_ty: TypeId }` — the erased
   value is a slot carried inside the cell itself. There is NO
   `Box<dyn Any>` behind a rut-minted box and no payload allocation to
   manage; the box's whole cost is the CELL, whose churn the arena
   free list already recycles (`alloc_slot`), and the heap accounting
   (RFC 0040) charges the same 8 bytes it always did. A planned
   "carry small payloads inline" repr change (native-fastpath phase 7)
   was examined and DROPPED: the lowering is already inline — there is
   no allocation to remove and no indirection to lift.
2. **Host payload boxes — an erased block, drawn from a bounded pool.**
   The embedder's `OpaqueBox::alloc(vm, v)` (RFC 0023/0026) moves `v`
   into a `Box<dyn Any>` behind `CellData::HostBoxed`; since the
   native-fastpath batch (phase 6) the block comes from an arena-
   owned, size-classed free list — a death (rc-0 release or arena
   teardown) runs the payload's destructor in place exactly once
   (RFC 0016 §3), then parks the exact-`(size, align)` block for the
   next mint of the same class. Bounded: payloads ≥ 256 B and ZSTs
   bypass, the pool trims at 512 parked blocks (~128 KiB worst case),
   and a dead arena deallocates its pool remainder — host memory is
   bounded by the churn's standing demand. This is the tier where host
   structs live (`NativeTable` — the nmap host map's storage, plugin
   state, host-fn returns); the rut surface never sees the
   difference.

The tiers are an implementation record, not new surface: the IR
contract above is unchanged (boxes are never re-sealed; `downcast`
stays pure), and neither tier adds a runtime union kind or a
crossing-visible difference.

## Amendment (2026-09-22, refval-round2): `downcast` yields `?T`

`opaque.downcast<T>(o) -> ?T` — the recovery is the **nullable**
(RFC 0044), not a `(T, bool)` product. This supersedes the tuple
surface above in place; the tuple spelling diagnoses as the removed
shape at any stale use site that survives migration.

- **A match is the box's own inner cell — the alias law.** The
  recovered `?T` shares the box: writes through the recovery are the
  source's, in both directions, through every holder (the one-cell
  law). A primitive payload reads the value — the bits copied at
  `opaque(v)` construction — so value semantics holds where aliasing
  is unobservable (RFC 0044 §5's primitive law).
- **A mismatch is `nil`.** The zero-value-on-`false` `.0` semantics
  DIES with the tuple: there is no flag and no zero value — the miss
  is the nullable's null, propagated by the ordinary `?T` laws
  (guard with `v != nil` / `when v { .. }`; an unguarded dereference
  traps `NilDeref`, never a silent zero). Host payload boxes miss the
  same way (`nil` for every `T` — the sentinel check unchanged).
- **Why.** The tuple was a *product*, and products allocate cells:
  every call minted a fresh `(T, bool)` record — one allocation, a
  field copy, a bool, and RC traffic per call, measured at **~+175
  ns/get** in the refcolumn round-1 attribution (the cost that helped
  kill the val-column experiment). `?T` is the language's native
  optional carrier: the lowering is now the reified-type-id check
  (RFC 0015) plus an **alias handoff** — the box handle moves with one
  retain; the mismatch branch is the null slot. **No allocation on
  either branch.** (The `?T` auto-deref reads the box's payload slot —
  the nullable use sees the box as its field 0.) Module format
  VERSION 7 invalidates v6 caches (the declared-surface change; the
  5→6 precedent).
- **Migration.** `(v, ok) = opaque.downcast<T>(o)` destructures become
  the nullable guard — `v = opaque.downcast<T>(o)` with
  `when (v != nil) { true -> .., else -> .. }` (or an `if`); `.0`
  projections become the recovery itself (auto-deref makes `v.x` read
  through); `.1` probes become `v != nil`. `x is T` is unchanged.

## Amendment (Sep 2026, nmap-hostvals): the store repr — RutOpaque/HostOpaque, the anchor cell dies, `Opaque<T>`'s checked borrow

Landed (docs/nmap-hostvals-report.md; phase `2a4716a`). The erasure
box's REPR changed under the frozen contract above; the IR surface
(downcast's purity, the ?T recovery, `x is opaque` naming the box) is
untouched.

- **One store, two kinds.** The rut-side `opaque` value addresses a
  store entry directly — `OpaqueEntry::Host(HostOpaque)` (a HOST
  payload: `Box<dyn Any>` + `type_name` + the optional finalize thunk)
  or `OpaqueEntry::Rut(RutOpaque { slot, val_ty })` (a RUT value held
  host-side — the shape this RFC's internals named, re-seated). The
  two-kind law, once spelled as `from_handle`'s error string, is an
  exhaustive match: a Rut entry answering a Host decode carries the
  verbatim `downcast<T>` recovery text.
- **TypeId lives ONLY on the Host path** (the borrow gate). The
  rut-side downcast reads the entry's runtime kind (for a Rut entry,
  the held cell's own type); the any arms consult the call site's
  static TyKind (RFC 0023's amendment). Never Rust types on the value
  path.
- **The anchor's death.** `CellData::HostBoxed` and
  `CellData::OpaqueBox` are DELETED from the cell enum — the header
  bullet above ("internals keep their names") holds for `TY_OPAQUE`,
  `Value::Opaque`, and `RutOpaque`, but `CellData::OpaqueBox` is gone:
  the arena anchor cell this RFC described no longer exists. The typed
  view `OpaqueBox<T>` is deleted with it; **the typed view is
  `Opaque<T>`**, whose checked borrow is the SAME law in the new home:
  `payload.is::<T>()` / `downcast_ref::<T>()` via the Any vtable, the
  trap naming both sides ("host box holds `X`, not `Y`"), borrow
  guards resident on the entry. One allocation and one indirection
  fewer per opaque.
- **Identity and rc.** Identity is word equality on the TAGGED slot
  word (bit 0 marks the store; entries are 8-aligned; nil stays
  all-zero) — exactly the old pointer-identity law. The tagged word is
  self-identifying, so `Heap::retain`/release route to the entry's own
  rc with one branch and every generic rc path (registers, record
  fields, array elements, closure captures) keeps its type-free
  discipline. Death runs the payload's `finalize(heap)` BEFORE the
  Box's own Drop (RFC 0016 §3's ordering, preserved by construction;
  its amendment records the walk); a Rut entry's held slot releases
  through the same walk.
- **The payload shape, disclosed.** The entry's payload is
  `Box<dyn Any>` + an optional monomorphized finalize thunk, not a
  `HostPayload`-bounded box — the suites pin primitive/`Vec` mints and
  the orphan rule forbids the test-side impls. The observable law is
  identical: payloads opt in to finalize; plain mints get the no-op
  default. Host payloads stay per-map/per-logger, never per-op.
