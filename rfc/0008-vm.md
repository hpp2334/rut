# RFC 0008: VM — Execution, Loading, Embedding Loop

- **Status:** Draft
- **Date:** 2026-08-21
- **Author:** hpp2334
- **Depends on:** RFC 0007 (bytecode), RFC 0004 (memory), RFC 0003 (tasks),
  RFC 0005 (host)
- **Implementation side:** heap internals in RFC 5004, coroutine internals
  in RFC 5003, dispatch internals in RFC 5002.

## Summary

One struct, one thread, one heap:

```rust
pub struct Vm {
    types:  TypeTable,               // global RutType descriptors + vtables
    heap:   Heap,                    // RFC 5004 §1 — RC + cycle collector
    mods:   Vec<Module>,             // linked images (RFC 0007 §5)
    frames: Vec<Frame>,              // the call stack
    ready:  Deque<TaskId>,           // woken coroutines (RFC 0003 §2)
    budget: Budget,                  // §6 — ops, deadline, interrupt
    host:   HostHooks,               // §5 — loader, timers, native mods
}
```

A `Vm` is `!Send` by construction (workers are separate VMs — RFC 0003
§5). Everything the host needs is methods on it; nothing else is public.

## 1. Frames & the interpreter loop

```rust
struct Frame {
    func: &'static FuncImage,        // linked code (RFC 0007 §5)
    pc: u32,
    regs: Vec<Slot>,                 // typed per the signature; verified
    state: u8,                       // suspend resume state (RFC 5003 §2)
    task: Option<TaskId>,            // frames may belong to a coroutine
}
```

The loop is a `match` over decoded ops (`decode` is a table index, not a
byte scan). Calls push frames; `ret` pops; ref discipline is emitted by the
compiler and asserted in debug builds (RFC 0004 §7). Direct calls are an
index + jump; interface calls are two loads + indirect jump (RFC 5002 §2);
host calls cross `Value` (RFC 0005 §3).

## 2. Traps

Arithmetic overflow (RFC 0002 §8), `Option.value` on `None`, failed
assertions, `panic(...)`, stack/budget exhaustion, and verifier-impossible
states unwind as `Err(Trap)` — not Rust panics. The trap carries a rut
backtrace (frame pcs → function names, rendered with source spans via the
image's tables). **Traps are catchable only at the host boundary** (RFC
0001 P4): a `vm.call(...)` returns `Result<Value, Trap>`; rut code never
catches one. Coroutine frames are dropped on the way out — destructors run
(RFC 0004 §3).

## 3. Coroutines & scheduling

- Every suspend entry runs as a `Task`: a root `CoroutineFrame` parked when
  `await` returns `Pending`. Wakers push `TaskId`s into `ready` (RFC 5003
  §4) — there is no microtask queue and no job executor.
- `spawn` creates a task; `cancel` marks it and drops the frame at its
  next suspension point; `select` is implemented in the VM because losers
  must be dropped atomically with the winner's resolution (RFC 0003 §3).
- Timers (`sleep`) are host-provided (§5): the VM never owns a clock.
  Tests virtualize time by faking the timer hook — full determinism.

## 4. Workers

`spawn_worker` (RFC 0003 §5) is a host hook: it constructs a new `Vm`,
loads the worker module, transfers arguments (move semantics on
`bytes`/`Array`, rc==1 checked — RFC 0004 §2), and returns `Sender`/
`Receiver` pairs backed by OS channels. Channel ops inside the VM are ops
(`chsend`/`chrecv`); when no value is ready, `chrecv` parks the frame like
`await` (wakers are the channel's, not timers').

## 5. Host hooks & module loading

```rust
struct HostHooks {
    load_module: fn(&mut Vm, &str) -> Result<ModuleHandle, Trap>, // §6
    now_ms:      fn(&Vm) -> i64,             // monotonic; virtualizable
    set_timer:   fn(&mut Vm, TaskId, i64),   // sleep → timer wheel
    interrupt:   fn(&mut Vm) -> bool,        // §6 — cooperative stop
    log: Option<fn(&Vm, name: &str, level: Level, msg: &str)>,  // std:log
}                                           // sink; None = silent no-op
```

- **Loading executes nothing** (RFC 0002 §1.1): `load` verifies and links
  an image; the host then calls an entry explicitly (`vm.call("main", ..)`,
  sync or suspend).
- Import specifiers (`"std:fs"`, `"imaging"`, `"./state"`) are resolved
  entirely by `load_module` — the VM has no filesystem access and no
  builtin loader policy (RFC 0001 OQ-4 stays a host decision).
- **Native specifiers resolve to decl modules** (RFC 0005 §5):
  `"plugin:my_map"` → `plugin/my_map.rut`, compiled and verified like
  any module — extern declarations are pure surface, so checking needs
  no Rust. The **link** step then proves every extern member *referenced*
  by the image has a registered implementation, signature-equal under the
  crossing rule (RFC 0005 §5.1) — a pure data compare against the
  ClassTable reflection. Missing: `no implementation bound for
  'plugin:my_map.MyMap'` (a load error, not a runtime trap).
- Cyclic imports are a link error (module set must be a DAG at the image
  level).

## 6. Budgets & interrupts

- `Budget { max_ops: u64, deadline: Option<Instant>, interrupt_every: u32 }`
  checked every `interrupt_every` ops (default 1024): over budget →
  `Err(Trap::Interrupted)` with the frame parked, **resumable** — the loop
  state is the frame, so the host can continue it later (`vm.resume()`).
- `interrupt()` lets a UI host yield mid-frame (16 ms slices) and tests
  cut infinite loops; native fns run outside the budget and are expected
  to be fast (RFC 0005 §2).
- `run_until_idle()`: drain `ready` + all non-suspended frames until
  nothing is runnable. `poll(deadline)`: like `run_until_idle` but bounded
  by wall time. These are the only stepping verbs (RFC 0001 "Host
  stepping").

## 7. Heap & collector integration

RC ops are inline in the loop; a `release` to zero runs `dispose()` then
frees (RFC 0004 §3). Suspect-list growth triggers the cycle collector
between frames only — never mid-function (borrow guards, RFC 0005 §3, stay
trivially sound). `vm.collect_cycles()` lets the host force a pass.

## 8. Embedder surface (summary)

| call | purpose |
|---|---|
| `Vm::new(host)` | construct; host owns hooks |
| `vm.load(spec) / vm.load_image(bytes)` | verify + link (§5, RFC 0007 §8) |
| `vm.call(name, &[Value]) -> Result<Value, Trap>` | sync entry |
| `vm.spawn(name, args) -> TaskHandle` | suspend entry; poll via §6 |
| `vm.run_until_idle() / vm.poll(deadline) / vm.resume()` | stepping |
| `vm.register_module(name, native)` | native fns (RFC 0005 §2) |
| `vm.register_struct::<T>()` | repr-C layout check (RFC 0005 §4) |
| `vm.collect_cycles()` | force cycle pass |

Errors are values (`Result`), bugs are traps, and the host is always in
charge of time, IO, and lifetime — the embeddability pillar (RFC 0001 G8).

## Open questions

- OQ-1: frame reuse pool vs fresh `Vec<Slot>` per call — measure on
  recursive corpus code (quicksort, matrix-mul).
- OQ-2: `chrecv` fairness across multiple awaiting receivers — FIFO per
  channel proposed.
- OQ-3: `Trap::Interrupted` resumption granularity — mid-expression is
  fine (frames are resumable) but native-fn boundaries are not; document
  exact guarantees.
- OQ-4: `Vm::clone`-free snapshots for debugging/time-travel — defer.
