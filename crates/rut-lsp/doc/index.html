1The big picture

rut-lsp is the language core behind the rut tooling: the queries an editor asks (hover, completion, go-to-definition, references, inlay hints, signature help, diagnostics), the actor that owns the session, and the JSON wire the hosts speak. It is one crate with no wasm coupling — the wasm-bindgen face (rut-lsp-wasm, the exported RutLsp class) is a thin delegation layer beside it.

The surface law. The crate's entire public surface is Lsp + env::Io. Everything else — semantic, hover, query, wire, the state — is private impl. The hosts' whole world is the Lsp handle and its JSON envelopes (Strings), so no internal type can ever leak onto the wire.

The layering, bottom-up:

┌──────────────────────────────────────────────────────────────────────────┐
│  host (VS Code extension · demo playground · native tests)               │
│      owns the editor, the watchers, the findFiles scan                   │
└───────────────┬──────────────────────────────────────────────────────────┘

┌───────────────┴──────────────────────────────────────────────────────────┐

└───────────────┬──────────────────────────────────────────────────────────┘

│  rut-lsp :: query/        hover · complete · definition · references ·   │

One tree per document, kept edited; every query is a read over it.

Two ideas organize everything:

  • The tree is the truth. A document is parsed once per change into a slot-mapped Ast (stable handles, a TreeIndex for position→node walks). Queries never re-parse and never scan tokens — they walk node_at(pos) → ancestors → downcast and read verbatim text as span × src joins. The only token residue is Doc::name_at; outside the classifier, no lsp code matches Tok::.
  • Doors are questions. Cross-file knowledge lives in DefIndexCollection doors (type_decl, functions, member, …) — one home per question, each with its preference baked inside. Consumers ask; they never re-derive.

2The actor & the session

An LSP serves a long-lived editing session, so the instance owns its state for its lifetime. But the host's Lsp is only an inbox handle — a cloneable sender — while one long-lived loop task owns the SessionState exclusively:

   host                        Lsp (mpsc sender)                 event_loop task
  ──────                       ─────────────────                 ───────────────
  analyze(uri, src)  ──post──► Msg::Cmd(Analyze, oneshot tx) ──► sync → run query
  await ◄───────────── oneshot reply (JSON string)  ◄──────────  answer, next msg
  • Every Lsp method is an async RPC bridge: own the arguments, post one message, await a oneshot reply. Handlers are sync bodies over &mut SessionState, so no bridge can borrow across an await.
  • Calls serialize FIFO on the loop. A dropped loop answers the loop-gone error envelope; a panicked handler isolates to its own reply channel.
  • Messages are three: Msg::Cmd (the business requests), Msg::SetEnv (hand over the host environment), Msg::Wake (the loop's self-address — the clock firing a deferred task).
  • Lsp::boot(spawn) takes the executor as a closure: the wasm face hands it wasm_bindgen_futures::spawn_local; native tests take a pool via Lsp::spawn_native.

SessionState

pub(crate) struct SessionState {
    docs: HashMap<String, MountedFile>,   // OPEN documents — the versioned cache
    defs: DefIndexCollection,             // prelude + walked/workspace files
    lock_pins: BTreeMap<String, String>,  // url → pin, from rut.lock
    direct_deps: HashSet<String>,         // the root manifest's dep names
    hints_shown: HashSet<String>,         // once-per-reason hint gate
    walk_task: Option<DeferTask>,         // the deferred dep-walk handle
}
  • Boot pre-mounts the engine prelude — core alone, the one ambient package. Every other std package rides the dep lane like any third-party library.
  • The sync lane is the doc-sync law: text arrives → sync (one incremental edit) → queries read. One parse per change, never per query — the burst of queries riding one version re-derives nothing.
  • The dep lane is deferred and coalesced: reload_deps posts a walk that defers under a 200 ms window (the injected clock's wakeAfter) and coalesces — a later reload supersedes an outstanding one. The walk is read-only over the host environment (§8) and mounts what it finds into defs; url deps it cannot fetch become missing rows plus a once-per-session hint: run rut install.

3The document pipeline

The heavy lifting lives one crate down, in rut-ast's Doc — the pipeline owner. rut-lsp's semantic::Document is a shell around it:

pub struct Document {
    doc: Doc,                            // src (normalized) · toks · ast
    lines: LineIndex,                    // byte offset ⇄ (line, UTF-16 col)
    spans: OnceCell<Vec<(Span, TokenType)>>,   // semantic tokens, lazy
    symbols: OnceCell<Vec<Symbol>>,              // document symbols, lazy
    inlays: OnceCell<Vec<RawInlay>>,             // inlay pass, lazy per version
}

Parse: one entry, recovery always on

Document::parse(mode, src) takes the source by value (it moves into the artifact) and rides Doc::parse: one lex, then the frame-machine grammar over the full range. The mode is the filename convention — mode_of: a *.d.rut path parses in declaration mode (Mode::Decl, surfaces only), everything else full Mode::Impl. Recovery is not a knob: broken code still yields a tree — error fences cover the unparseable regions, and incomplete shapes are real nodes with absent slots (recv. mid-typing is a MethodNode whose member is None).

Sync: one edit in, a coherent view out

When the editor reports new text, Document::sync(text) does exactly four things:

  1. Edit::between(old, new) — diff the texts into one Edit { start, old_end, text } (common prefix/suffix, char-boundary snapped);
  2. Doc::edit(edit) — the ONE mutator: splice the source, splice the token stream (relex from a line boundary outside any literal, shift the tail), find the dirty root item, reparse just that window into fresh slots of the live store, and splice the new subtree under the surviving parent;
  3. rebuild the UTF-16 LineIndex;
  4. drop the lazy views — the first read after the change re-derives them, never yesterday's spans.
Edit ≡ cold. The incremental lane is pinned equal to a cold parse by property tests (rut-ast/tests/doc_edit_props.rs, rut-lexer/tests/splice_props.rs): random edit sequences must land the same tokens, spans, tree, errors and index as parsing the result from scratch.
editor text ──didChange──► sync() ──► Edit::between ──► Doc::edit
                                                    ├─ src splice (Source::edit)
                                                    ├─ token splice (window relex)
                                                    ├─ dirty root item found
                                                    ├─ window reparse → fresh slots
                                                    ├─ subtree spliced under parent
                                                    └─ TreeIndex invalidated (lazy)
                                          ▼
                          one coherent Document for the whole query burst

Reading the document

Doors are questions — there are no raw src()/toks()/ line_starts() handouts. Text is doc.text(span) (the verbatim join), lines are line_of/line_span, position math goes through the UTF-16 LineIndex, and the expensive views (semantic-token spans, the symbol tree, the inlay pass) are OnceCell-lazy — a lane that never reads them never pays for them (the dep-walk index pass parses hundreds of dep files and reads only src/toks/ast).

4The world: files & the chain

Every file in the session's world — the open document, the prelude, walked deps, workspace-indexed files — is one shape:

pub(crate) struct MountedFile {
    pub(crate) doc: Document,   // the kept tree (the pipeline owner)
    pub(crate) mount: Mount,    // the provenance stamp: origin/module/mod_path/mode
    pub(crate) decls: DeclMap,  // name → node addresses, built once per version
}

The DeclMap is the small pass that replaced the old row extractor: walk the root items once, record node addresses (types, fns, lets, uses, mods) in source order. Nothing else is stored — every other fact (text, line, visibility, ambient-ness, docs) is derived at read through typed views over (doc, AnyHandle): TyView, FnView, MemberView, LetView, UseView, ModView. A view's verbatim text is a span × src join on the owning file's document; its line is doc.line_of; its ambient/vis verdicts ride the node's modifier chain. Nothing stored, nothing stale.

DefIndexCollection owns the world's files (replace-by-origin on mount), and each query gets a Chain — an ordering view with the open document at the head and the world after:

let chain = state.chain(uri)?;   // head = the open doc's fresh entry
chain.type_decl("Circle")        // the mounted-over-embed preference inside
chain.functions("length")        // 0/1/many — a Vec, the honesty rule
chain.module_let("PI")           // unique-or-none — ambiguity is a miss
chain.member(pos, node)          // THE member door (§5)
One home per preference. type_decl carries the mounted-over-embed rule (a real mounted dep outranks the ambient prelude answer), functions the 0/1/many honesty rule, module_let unique-or-none, and prefer_bodies the body-over-decl rule (a package indexing both its .d.rut surface and its mod.rut body answers from the body). No consumer re-implements any of these.

5The member law

Hover, go-to-definition and completion all need to answer the same question: where does this member actually declare? They share one resolver — Chain::member(pos, node) — with one rule that mirrors the compiler's:

The member law. Members of type T = T's own surface (class body, builtin) ∪ inherent impl T { .. } methods. On an interface I they are exactly I's declared signatures — use-gated when I is foreign (satisfaction is structural, so no impl joins the two).

The door consumes nodes, not derived facts: the caller hands the node the cursor's walk found (a MethodNode, a FieldNode, or a :: path's tail segment). The member and receiver derive inside; the receiver's type resolves inside — self → the enclosing type, literals → primitives, single-segment paths → the locals pass (Doc::bindings(), read internally, never a caller-run pass) then module lets. The answer is a verdict:

enum MemberHit<'a> {
    Found(MemberTarget<'a>),  // Member | EnumMember | ImplFn | IfaceMember
    None,                    // final miss — the receiver's type is known
    UnknownReceiver,         // caller may fall through to the bare-name search
}

The use-both gate rides the interface lane: a foreign interface's members resolve only when this document names the interface in a use; an interface declared in this document is in scope natively.

6The queries

One module per request family under src/query/; analysis.rs is the aggregator the ABI calls. All of them consume the chain and answer LSP-shaped values (from the ls-types crate) serialized as-is.

analyze(uri, src) — diagnostics, tokens, symbols

The editor's heartbeat: store the doc (the sync lane) and return the triple { diags, tokens, symbols }.

  • diags — the parse panel (ast.errors(), the flat ordered view) merged with the check lane (type-shape findings: unknown names, missing members, arity mismatches) when the dep world is mounted.
  • tokens — the semantic-token stream: classify(toks, ast) colors every token through the tree (defs vs uses, self/Self, fields, fns, interfaces…). The legend (token-type names in index order) rides legend().
  • symbols — the document-symbol tree walked off the AST (decls with ranges; impl Circle heads a group).

hover(uri, line, ch) — verbatim markdown

The walk: node_at(pos) → ancestors → downcast; the name-position map (name_at) decides both what is under the cursor and the exact span to decorate. Rendering is tree-local and verbatim — a declaration's head/docs slice off the owning file's own source, never a pretty-printer:

// a 2D point
struct Point {
  x: f64;
  y: f64;
}

fn length(p: Point) -> f64 {
  return p.x;   // ← hover `x` here
}

Hovering the use-site x resolves the receiver p (a param, annotation Point), applies the member law, and renders the field's declaration verbatim with its owner:

```rut
x: f64
```
in `Point`
  • A class/type hover shows the decl head as written plus grafted doc comments (// a circle above class Circle { shows in the hover).
  • Use sites, decl sites and member sites all decorate exactly the hovered token — the unified name_at mapping.
  • A miss is an empty hover (null), never wrong text — the heuristic contract shared with the classifier.

definition / typeDefinition

Same resolver family as hover: name positions resolve through Doc::bindings() (locals, shadow-correct), the collection doors (type_decl, functions, module_let), the member door, and the use-graph walk for imported names (matches_pkg — module name first, origin/stem derivation on an unnamed file). Answers are Location { uri, range } rows; location views compute their line/range internally over the owning document — cross-file jumps open the mounted dep, no re-parse. get_declaration is consciously absent: the wire spells no declaration request, and the body-vs-surface pick policy is isolated in prefer_bodies for the day one arrives.

references(uri, line, ch, include_decl)

One scan across every mounted file: the position resolves to a symbol key, then each file's name positions stream through the same shadow-correct resolve. The per-candidate chain is Chain::reordered — the candidate file at the head, so locals resolve in their own file's context. No file is ever re-parsed for a references scan; the mounted world already holds every tree.

inlay(uri, range) — the lazy per-version pass

Inlay hints are a document pass, not a position query: the shell computes the whole document's rows once per version (Document::inlays_view, an OnceCell dropped on sync) and the requested range is just a viewport filter over the cached rows.

let c  = Circle::new(1.0);   // ← hint: : Circle
let n  = 42;               // ← hint: : i64
log.info(f"r={c.r}");       // ← param hint: message
  • The trigger is a normal absent slot: a LetStmtNode whose annotation is None. The resolver doors (expr_ty, the callee's written return) fill the type.
  • Call sites get parameter-name hints priced against the callee's declared params.
  • Inferred text (source-less) is the one sanctioned render — everything else in hover/completion stays verbatim.

signature_help(uri, line, ch)

A CallNode ancestor with the cursor among the argument spans; the active argument is counted from child spans, and unclosed calls ride rparen: None (the incomplete shape — signature help works mid-typing). The signature shown is the callee's verbatim src(); params come from the AST's own param list.

7Completion, tier by tier

Completion is the widest query, so it is organized as: one edge probe (decide what kind of position the cursor is), tier doors (enumerate + gate, in the collection), and one conversion at the ABI edge (tier rows → CompletionOut wire items). Prefix filtering is presentation, at the call site — the doors never filter.

Step 1 — the typing edge

typing_edge(chain, pos, src) walks the tree: the byte before the cursor lands the probe (skipping structural wrappers up to 16 bytes back — the blank after a colon, the gap at EOF), then the node's own kind names the tier:

EdgeRecognized asExample

Step 2 — the tiers

The bare tier — Edge::Bare

The merged list under the compiler's bare-name law, in precedence order, deduped by label (first occurrence wins):

interface Shape {
  fn area(self) -> f64;
}
entry fn main() -> nil { ⏐ }
  • locals — every binding visible at the cursor, shadow-correct (innermost in-scope decl per name wins; a binding whose own declaring ident holds the cursor stays off), each with its declared-or-inferred type as the detail;
  • keywords — the grammar's reserved set, one canonical list (interface, use, impl, let, fn, async, …; retired spellings never appear);
  • visible decls (Chain::bare) — the open document's own decls, the chain's ambient builtin rows (prelude builtin names bind with no use), and the names the document already uses, matched (name, pkg) against the head's imports. In the example: Shape (as an interface) and main complete; area does not — methods are reached through a receiver, never named bare;
  • auto-import — every other foreign name, offered only from direct deps, with a use mod::Name; insert riding additionalTextEdits and a sort key that lands it after every local item.
The dot guard. A bare request sitting right after a . the tree could not shape (a fence swallowed the receiver) is a MEMBER request with an unresolved receiver: the answer is an empty list — never the bare keyword dump.

The member tier — Edge::Member

chain.members(pos, node): the member/receiver derive inside the door, the receiver resolves through the shared resolver (§5), and the gates live in the member law:

struct Counter {
  n: i32;
}
impl Counter {
  fn bump(self) -> i32 { return self.n; }
  fn reset(self) -> nil { }
}
fn use_it(c: Counter) -> i32 {
  return c.⏐;      // → n (field) · bump · reset (impl methods)
}
  • An unresolved receiver is an EMPTY tier, never a wrong one; the typing edge c.⏐ (absent member) enumerates the full list.
  • An interface receiver lists exactly the declared signatures — gated by the use-both rule when the interface is foreign.
  • A receiver that resolves as a module head (helpers::mk( — positions qualify with ::) diverts to the position-path tier below.

The use tiers — Edge::Use

Keyed on the use node: the walk derives from the node's own recorded spans (the segments before the cursor — a trailing partial ident is the typed prefix, never a walk segment).

use ⏐;              // → the chain's module names (deps, prelude)
use json::⏐;         // → json's public exports + walkable mods
use json::{ en⏐ };   // → encodeJson, decodeJson, … filtered by "en"

Only pub names cross a package boundary (fns, lets, types, and pub use re-exports alike — one gate, no legacy shape); deeper segments walk the package's mod namespaces (use gadgets::layout::⏐ walks layout only).

The :: tiers — Edge::Qualified

Three attempts, in order — a resolved head is final (the filtered list is the answer even when empty):

  1. Position-path (intra-package): the head resolves to a module of the doc's own package (or a dep module the doc bound via use calc::{ math }) → that module's members visible to the current file: private reaches the declaring module and descendants, pub(super) the parent's subtree, pub(pkg) the package, pub everywhere.
  2. Type head: Color::⏐ offers the enum's members; Counter::⏐ offers statics plus the inherent impl fns; an interface head offers nothing (its members ride receivers).
  3. Fallthrough: an unknown head with :: falls through to the bare tiers, the typed prefix riding along.

The type tier — Edge::Annotation

At an annotation boundary (let x: ⏐, id: u⏐, fn f() -> ⏐): the parser's primitive table (the one PRIMITIVE_TYS), the document's own types, the ambient builtin rows, and the foreign types the document already uses. Keywords, fns and locals stay off — values never ride a type position.

Step 3 — one conversion

Every tier produces rows — views over the decls they found, plus keyword and binding rows — all answering one trait:

pub(crate) trait CompletionRow {
    fn name(&self) -> &str;          // borrowed — no allocation
    fn detail(&self) -> String;      // verbatim signature / field / kind+type
    fn docs(&self) -> Vec<String>;   // grafted doc lines
    fn kind(&self) -> CompletionKind; // Type/Interface/Fn/Method/Field/…
}

The only place a label allocates is CompletionOut::of(row) at the ABI edge — one vocabulary, one allocation point. The wire item carries sortText (auto-import sorts last) and additionalTextEdits (the auto-import's use insert, placed after the local items, coordinates over the same normalized source every other range rides).

8The wire & the three ABI lanes

Every Lsp method answers a JSON String — the envelope. The shapes that are ours live in wire.rs (one place spells every field name; the e2e wire-shape gate asserts the exact key sets through the shipped wasm). Query answers (hover/completion/diagnostic/symbol values) are ls-types values serialized as-is. Errors narrow on the {"error": "…"} key.

TS// the wasm face — one exported class, every method a thin delegation
const lsp = new RutLsp();
await lsp.setEnv(env);                          // the read-only HostEnv (below)

const analysis = await lsp.analyze(uri, src);
// → {"diags":[…],"tokens":{"data":[…]},"symbols":[…]}

const hover = await lsp.hover(uri, 9, 15);      // → LSP Hover JSON, or null
const items = await lsp.complete(uri, src, 9, 15);  // takes src ALWAYS (doc-sync law:
                                                   // completion fires on the keystroke)
const locs  = await lsp.definition(uri, 9, 15); // → [{uri, range}]
await lsp.forget(uri);                          // drop a closed doc
The three-lane ABI law. The public surface is exactly three lanes — provider queries (analyze, hover, complete, definition/typeDefinition, inlay, references, signatureHelp, legend, forget); workspace-scan push (indexFile, indexModAt, parseManifest — the host's findFiles respects editor-ignore semantics the env cannot); dep pull (setEnv + reloadDeps, the deferred door; resolveDeps stays as the eager manual door). No entry mutates dep state except through the injected env.

The read-only environment

The host hands setEnv one object — the capability the dep walk reads through:

TSinterface HostEnv {
    read(path: string): Uint8Array | null;    // miss = null, never throws
    readDir(path: string): string[] | null;   // null = no dir
    isDir(path: string): boolean;
    notify(message: string, isError: boolean); // the hint lane
    wakeAfter?(ms: number, wake: () => void); // optional clock — plain setTimeout
}

The grant is read-only by construction: no write, delete or fetch exists on the trait, so no handler can spell one. The clock is the one machinery addition — the host supplies the timer, but the actor owns every when: toward the host the actor only ever answers. An env without the clock degrades gracefully (every deferral runs eagerly).

What the walk does with it: read the workspace roots' rut.jsonc manifests, mount path deps by walking their files (honoring mod NAME; edges — indexModAt's answer names them for the host's scan), mount url deps from the global content-addressed store ($RUT_HOME, cache paths computed Rust-side), and report refused rows as MissingDep hints — the recipe, rut install, rides the notify lane once per reason.

9Hosting the core

  • The VS Code extension (integrations/vscode-extension/) embeds the in-process wasm (bin/rut-lsp.wasm), injects a read-only node:fs env, and maps envelope values to vscode.* types. It writes nothing, anywhere — a pure reader; its whole dep lane is watchers + reloadDeps.
  • The demo playground (demo/, deployed at playground.rut.hpp2334.com) imports the same wasm package and runs it in the browser — std packages mount from pinned source zips fetched from jsDelivr.
  • Native tests boot Lsp::spawn_native with their own Io mocks — the same door the JS face rides.

The laws in one breath

  • Surface: the crate is Lsp + env::Io; JSON Strings on the wire.
  • Sync: text arrives → sync (one incremental edit) → queries read; complete takes src always.
  • Artifact: Ast is pure structure; text is a span × src join on the owning document.
  • Capsule: nodes are POD; parse constructs, Doc::edit repairs; no field pokes.
  • Doors: one home per question; views derive everything at read; location views never expose the owning doc.
  • Tokens: name_at is the fence residue, tokens_in the classifier's window — no other token reading crosses rut-ast.
  • Heuristics: a miss is empty/null, never wrong text.

Gates that keep it honest

  • cargo fmt --all --check · cargo clippy --workspace --all-targets (+ the wasm32 lane) · cargo nextest run — warnings are errors.
  • The extension release lane: build:wasm → grammar corpus + through-wasm e2e (123 corpus files, the wire-shape block asserting every envelope's key set) → vsce pack, byte-verifying the wasm inside.
  • Edit ≡ cold property suites over corpus fixtures (both stages of the incremental pipeline).
